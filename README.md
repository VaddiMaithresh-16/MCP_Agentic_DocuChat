# Agentic RAG DocuChat with MCP and Memory

Agentic RAG DocuChat is a Python CLI application for asking questions about a PDF document. It combines document retrieval with Chroma, HuggingFace embeddings, Gemini through LangChain, LangGraph memory, and Tavily search tools loaded through Composio.

## Features

- PDF loading with `PyPDFLoader`
- Text chunking with `RecursiveCharacterTextSplitter`
- HuggingFace embedding model support
- Persistent Chroma vector store
- Gemini chat model through LangChain
- Tavily search tools through Composio
- LangGraph in-memory conversation checkpointing
- `.env` based configuration
- Query via `--query` flag, or interactive prompt if not given

## Project Structure

```text
MCP_Agentic_DocuChat/
├── main.py
├── requirements.txt
├── README.md
├── .env.example
├── .gitignore
├── data/
│   └── research_paper.pdf
└── chroma_langchain_db/
```

Notes:

- `.env` is ignored because it contains secrets.
- `chroma_langchain_db/` is generated by Chroma at runtime.
- `DOCUMENT_PATH` accepts either a **local PDF file path** (e.g. `./data/research_paper.pdf`) or a **direct PDF URL** (e.g. `https://example.com/paper.pdf`). `PyPDFLoader` auto-detects which one it is — no config flag needed.

## Requirements

- Python 3.11 or newer
- Google Gemini API key
- Composio API key
- Composio user id with Tavily access configured

## Setup

Clone the repo:

```bash
git clone https://github.com/VaddiMaithresh-16/MCP_Agentic_DocuChat.git
cd Agentic-DocuChat
```

Create and activate a virtual environment.

macOS or Linux:

```bash
python3 -m venv avenv
source avenv/bin/activate
```

Windows PowerShell:

```powershell
python -m venv avenv
avenv\Scripts\Activate.ps1
```

Install dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Environment Variables

Create `.env` from the example file:

```bash
cp .env.example .env
```

Update the values:

```env
GEMINI_API_KEY=your_gemini_api_key
COMPOSIO_API_KEY=your_composio_api_key
COMPOSIO_USER_ID=your_composio_user_id
HF_TOKEN=your_huggingface_token

EMBEDDING_MODEL=sentence-transformers/all-mpnet-base-v2
GEMINI_MODEL=gemini-3.1-flash-lite

DOCUMENT_PATH=./data/research_paper.pdf
```

`HF_TOKEN` is required for gated/private HuggingFace models, and recommended even for public ones to avoid Hub rate limits. Get it from https://huggingface.co/settings/tokens. `HuggingFaceEmbeddings` picks it up automatically from the environment — no code change needed.

### Where to Get Each Key

| Key | Get it from |
|---|---|
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey — Google AI Studio, free tier available |
| `COMPOSIO_API_KEY` | https://app.composio.dev — Dashboard → Settings → API Keys |
| `COMPOSIO_USER_ID` | Composio dashboard → your account/user id, or generate one via Composio SDK on first auth |
| `HF_TOKEN` | https://huggingface.co/settings/tokens — create a token with "Read" scope |

Tavily access must also be connected inside your Composio account (Composio dashboard → Toolkits → Tavily → Connect) — this app loads Tavily tools through Composio, not a direct Tavily API key.

## Running

Run without a query — you'll be prompted to type one:

```bash
python main.py
```

Or pass the query directly from the command line:

```bash
python main.py --query "Summarize the main contributions of the paper."
```

Another example:

```bash
python main.py --query "Compare this paper with GraphRAG."
```

## How It Works

1. Loads environment variables from `.env`.
2. Loads the PDF from `DOCUMENT_PATH`.
3. Splits the PDF into chunks.
4. Creates embeddings using `EMBEDDING_MODEL`.
5. Stores chunks in Chroma under `chroma_langchain_db/`.
6. Loads Tavily tools through Composio.
7. Creates a LangChain agent with memory.
8. Answers the query from `--query`, or prompts you for one if not given.

Note: `main.py` checks Chroma for existing embeddings before ingesting. If chunks already exist for the collection, it skips re-ingestion and prints a message instead of re-embedding the PDF. Delete `chroma_langchain_db/` manually if you want to force a fresh re-index of a changed PDF.

## Troubleshooting

### Missing Environment Variable

If you see `Missing <VARIABLE_NAME>`, check that `.env` exists and includes every key from `.env.example`.

### Missing or Unreachable PDF

`main.py` catches PDF load failures and exits with a clear message instead of a raw traceback:

- Local path doesn't exist → `DOCUMENT_PATH not found: ...`
- URL unreachable / times out / DNS fails → `Could not fetch DOCUMENT_PATH URL: ...`
- File exists but isn't a valid PDF → `Failed to load/parse PDF from DOCUMENT_PATH: ...`
- PDF loads but has 0 pages → `PDF loaded but contains no pages: ...`

Confirm `DOCUMENT_PATH` in `.env` points to a valid local PDF file or a direct PDF URL.

For the default local path:

```bash
mkdir -p data
```

Then place your PDF at:

```text
data/research_paper.pdf
```

### Dependency Error

Make sure the virtual environment (`avenv`) is active, then reinstall:

```bash
python -m pip install -r requirements.txt
```

### Fresh Chroma Index

To rebuild the vector database from scratch:

```bash
rm -rf chroma_langchain_db
python main.py
```
